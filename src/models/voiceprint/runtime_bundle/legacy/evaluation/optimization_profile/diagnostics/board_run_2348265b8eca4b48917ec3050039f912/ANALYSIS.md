# 07 优化对照与逐层剖析分析

数据：用户手动运行 PYNQ-Z2，RUN `run_2348265b8eca4b48917ec3050039f912`。八份原始结果从用户指定 Samba 路径只读复制到本目录，未执行开发板代码或修改共享文件。`analysis.json` 保存计算结果，`graph_inspection.json` 保存本地对应模型的只读结构检查。

## 结论

CPU 子图开启 ORT 全部图优化有收益，但尚未实现相对完整 INT8 CPU 的整网加速。V3 耗时减少 34.69%～35.42%，V4 减少 5.11%～7.52%。V4 ON 仍比 INT8 CPU 慢 39.49%～47.80%；V4 ON 相比 V3 ON 仅减少 2.68%～4.38% 的延迟。

当前分图存在可以明确定位的静态依赖处理问题：CPU 首块/FCM 后尾块的 1205 个输出中，1203 个来自与音频无关的静态依赖；抽查的四个主要 CAM 子图均有 25 个输入，其中 23 个是静态依赖。静态输入包含形状常量、偏置和反量化后的卷积权重。它们通过 Python 作为运行时张量传给下游 CPU 会话。开启优化开关不会自动把图输入恢复成初始化参数。

这些边界增加张量封装/复制工作，也很可能妨碍权重预处理、静态形状计算和部分图融合。结构问题已经确认；它对性能的具体影响以及修复收益尚未通过新的 A/B 试验量化。不能声称修复后一定超过 INT8 CPU。

## 正式模型耗时

每模式每录音 10 次，1 线程、两轮反序、无详细剖析与整数审计。范围是固定完整 Fbank → CAM++ → L2 → 余弦，不包括采集、读 WAV、Fbank 或首次加载。

| 模式 | speaker1_b 中位数/秒 | speaker2_a 中位数/秒 |
|---|---:|---:|
| 完整 INT8 CPU | 6.193 | 6.529 |
| V3 OFF | 13.990 | 15.183 |
| V3 ON | 9.035 | 9.916 |
| V4 OFF | 9.342 | 10.170 |
| V4 ON | 8.639 | 9.650 |

INT8_CPU / V4_ON = 0.71688 / 0.67661，小于 1。全部模式 RTF 大于 1。样本仅两条查询，不代表完整数据集或音频采集端到端速度。

## 慢层与图边界

以下为独立剖析阶段各项 3 次测量的中位数，不与正式计时混加。

| V4 ON 项目 | speaker1_b /毫秒 | speaker2_a /毫秒 |
|---|---:|---:|
| cpu000_after_fcm.onnx，包含初始 kernel=5 TDNN 与静态输出 | 708.54 | 750.98 |
| graph_37，block2/tdnnd23 CAM 段 | 109.39 | 117.25 |
| graph_36，block2/tdnnd22 CAM 段 | 107.73 | 114.92 |
| FCM /head/layer1/layer1.0/conv1/Conv | 234.07 | 249.50 |
| pointwise /xvector/transit2/linear/Conv | 163.15 | 194.79 |
| pointwise /xvector/transit3/linear/Conv | 163.08 | 194.86 |

V4 ON 中，全部点卷积 callback 的逐层中位数之和约 1.841 / 2.170 秒，FCM 约 1.674 / 1.794 秒。CPU 会话中位数之和约 5.178 / 5.549 秒；剖析与正式测量为独立采样，且元数据收集改变运行开销，不能据这些和倒算正式时延。

只读 ONNX 检查：

- 原 V3 首 CPU 块：1332 节点，1205 输出，1203 静态输出。
- V4 FCM 后 CPU 尾块：1213 节点，942 个 Constant、265 个 DequantizeLinear、一个 kernel=5 的 TDNN Conv；仍输出 1203 个静态张量和 2 个动态张量。
- graph_36/37/53/54：每个 25 输入，23 静态、2 动态；各包含局部 kernel=3 卷积、注意力分支两个 1×1 卷积以及池化、形状操作、Sigmoid、BatchNorm。
- 这些子图的量化 scale/zero point 仍在初始化参数中。发现的问题是权重反量化结果等静态值跨图作为输入，并不是把所有量化参数都变成了动态输入。

## 数值与硬件检查

- 100 个正式样本、30 条剖析记录数目与预期一致，原始样本与 performance.json 内嵌样本相同，重算中位数与 summary 一致。
- correctness.json 与 performance.json 中记录的哈希一致；setup、correctness、performance 身份一致。
- 12 个真实硬件审计案例（四个混合模式 × 三段录音）均记录当前逐层 INT8/INT32 精确匹配，对应软件整数模型的完整向量精确匹配。
- 五个整数参考自检全部通过。
- 优化漂移门限仍失败。V3 ON/OFF embedding cosine 约 0.99480～0.99693、relative L2 约 7.93%～10.18%；V4 约 0.99880～0.99898、4.53%～4.98%。
- V3 优化前后两条查询分数绝对变化 0.0029803、0.0077443；V4 为 0.0013430、0.0052476，均未满足现有 0.001 门限。
- 原 QDQ 严格漂移门限包括 CPU ON 在内均失败；工程时延不构成精度一致加速结论，不输出未经校准的身份决策。

## 下一轮优先事项

1. 在新目录重新生成分图：把原模型的静态依赖链放回使用它们的 CPU 子图，保留量化权重、参数和 Q/DQ 关系。避免只把反量化浮点权重写死，以免失去原量化结构。
2. 消除首块 1203 个静态输出及后续重复静态输入，仅跨 CPU/FPGA 边界传实际变化的激活与必要残差。重新计算图输出、输入、保活列表；按实际张量依赖验证，而非直接删名字。
3. 沿用同一 bitstream 做 OFF/ON A/B，先验证图重建、当前输入整数/硬件一致性和向量/评分变化，再正式测速。保留所有既有严格数值失败，不改门限。
4. 依据修复后的逐层结果，再决定 CAM 模块更大范围融合、PS 调度调整或 PL 访存优化。当前报告不能判定 PL 时段中算力与 DDR 等待的比例。

初始化另计：CPU INT8 约 28.9～29.1 秒，V3 ON 约 17.9～18.8 秒，V4 ON 约 27.3～29.2 秒；它们不在正式稳态模型时延中，也不是板卡上电冷启动时延。
