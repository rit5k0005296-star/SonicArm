# 第四版 FCM 上板验证

电脑解压 `fcm_v4_test.zip`，将解压得到的整个 `fcm_v4_test` 文件夹上传到板卡 SonicArm 目录下；不要覆盖旧版本。打开 `00_fcm_first_test.ipynb` 顺序运行三个代码格，先文件校验，再冒烟，最后完整FCM。

无需音频线、Vivado、联网pip、PyTorch或ONNX Runtime。输入是冻结的真实模型INT8边界，用于硬件设计验证。助手没有上板执行、写Samba或验证实际板卡。

验证范围：48组真实独立/递归参考，INT8及INT32逐点相等，调试开/关；两段12层实际连续FCM调用；2051帧小通道K3分块接缝；原V3一个代表层在双IP bit中的回归。RTL仅5组真实全通道/5帧用例及3组合成边界事务，完整300/67帧、48组仅完成C仿真，须由你完成上板验证。

FCM包含10个3×3和2个1×1投影。每次调用权重和后处理查找表缓存片上，输入使用4频点×32帧tile，8输出通道×4时间点=32个MAC通路。仍有逐层/残差分支DDR往返，尚未实现整个残差块驻留片上。

单输入256项LUT保留原Conv Q1之后的DQ/ReLU/Q；残差使用65536项二维LUT保留双方独立量化域的原DQ/Add/ReLU/Q，已穷举验证。该处理不消除卷积整数重建与原浮点QDQ的误差，不代表整网精度或鉴权验收。原300帧样例FCM输出212/96000元素不同、最大5LSB，已保留在reference_report.json；67帧样例一致。正式阈值未校准。

出现IP超时或运行中中断时停止，保持Notebook kernel直到板卡断电；DDR缓冲区可能仍被硬件访问。断电重启后再重试，不继续后续格。不并行运行其他FPGA程序。

返回完整输出及test_results/run编号/smoke.json、correctness.json。通过后再进入完整CAM++接入及同板CPU/V3/V4测速；本包没有测速或整网加速结论。
