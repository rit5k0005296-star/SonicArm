## 优化参数

比较学习率1e-4/3e-4和BatchNorm运行统计冻结/更新，共4组；v3原模型也作为验证候选，以免强行替换成更差模型。选中lr0.0003_freezeBNTrue，第17轮。AdamW，weight_decay=1e-4，batch32，最多80轮，cosine退火，早停18轮，每轮加权采样1280条。

采样质量分配为板上35%、新手机女声25%、旧真人20%、合成18%（未出现额外来源时总计98%，采样器自动归一化；合成质量一半分给unknown/silence）。各真人域内按类均衡。每条真人训练录音生成4种增强：速度0.92–1.08、轻度位移和增益，其中两种叠加22–35dB合成噪声及轻度延迟回声；再配合轻度时频掩蔽。合成噪声不是板上实录噪声，不冒充真实非指令负样本。

交叉熵加0.1倍教师蒸馏，蒸馏温度2只用于训练损失；推理温度为1。验证排序先比较2×板上正确数+新女声正确数+旧真人正确数，并惩罚合成非指令误判增加，再比较加权真实标签交叉熵。选择完成后只计算一次所选模型的测试结果，没有利用测试错误继续搜参。

合成非指令原始误判为指令数：2 → 3（unknown/silence共40条）。这不是现场误触发率，也不足以确定机械臂执行阈值。

## 上板使用

解压ZIP进入TCResNet_all_real_v4文件夹，整个文件夹一起更新，尤其不能混用旧model_weights.npz和新best_model.pth。板上只需NumPy、SciPy：

```bash
python3 tc_resnet_infer_wav.py /实际路径/录音.wav
```

电脑PyTorch版本：`python inference.py /录音路径.wav`（M4A/MP3还需FFmpeg）。两种入口使用同一标签顺序、前处理配置和训练权重；仍输出execute=false，仅做分类。

本地对全部149条真人回归录音验证NumPy与PyTorch：Top1全部一致，最大logit绝对误差0.00039386749；与表中真实类别分数最大偏差1.3709068e-06。这是本机验证，尚未在真实ARM板上实测速度或数值一致性。原始手机音频在验证时经FFmpeg转换为16kHz单声道浮点WAV。

## 后续优化顺序

1. 使用本版整包对新会话板上录音做外部测试，各目标指令增加至少20条，覆盖不同距离、音量与语速。把本次149条保留为历史回归，不能继续充当未见数据。
2. 对仍错的文件核对录音内容、标签和是否说完整；如果需要纠正标签，建立新版本清单，并另采外部测试，保留修改记录。
3. 重点补板上真实背景噪声、闲聊和相近非指令语句的unknown/silence，再用独立非指令录音选择执行阈值。只调高softmax分数不会自动修正分类错误。
4. 若新会话仍明显退步，优先检查板上与电脑是否加载同一包、16kHz单声道与相同对齐归一化。当前模型已很小，本轮保持结构以兼容板上推理；增加网络大小需要重新测延时、内存和泛化效果。
