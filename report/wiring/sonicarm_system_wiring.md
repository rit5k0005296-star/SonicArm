# SonicArm 系统总体接线与通信说明

## 1. 文档目的

本文档说明 SonicArm 当前系统的设备组成、物理接线、供电关系、软件与硬件通信流程，以及已经验证和仍待集成的部分。

配套示意图：

- `SonicArm_系统总体接线与通信示意图.png`
- `SonicArm_系统总体接线与通信示意图.svg`

系统以 PYNQ-Z2 为中心控制节点，完成有线耳机语音采集、CAM++ 声纹鉴权、TC-ResNet3 命令识别、触摸界面显示和安全状态调度。机械臂由 Arduino Nano 类控制板驱动，PYNQ 与 Arduino 之间规划采用 UART 通信。

## 2. 系统组成

| 编号 | 设备 | 主要作用 |
|---|---|---|
| 1 | 开发电脑 | Jupyter 调试、Samba 文件部署、串口日志查看 |
| 2 | PYNQ-Z2 | 系统主控、语音算法、FPGA 加速、显示和触摸管理 |
| 3 | 有线耳机麦克风 | 通过 3.5 mm TRRS 接口输入语音 |
| 4 | 5 英寸触摸显示屏 | 显示本地 UI，并通过 USB HID 返回触摸坐标 |
| 5 | Arduino Nano 类控制板 | 接收 PYNQ 的 UART 动作指令，控制机械臂舵机 |
| 6 | 多自由度机械臂 | 执行抓取、放置、复位等动作 |
| 7 | 独立电源 | 分别为 PYNQ、显示屏、Arduino/舵机供电 |

## 3. 总体系统结构

系统主数据流如下：

```text
有线耳机麦克风
      │ 3.5 mm TRRS 模拟音频
      ▼
PYNQ-Z2 / ADAU1761
      │ 48 kHz 采集，转换为 16 kHz 模型输入
      ▼
CAM++ 声纹鉴权
      │ 鉴权通过后
      ▼
TC-ResNet3 命令识别
      │ 命令映射与安全状态机
      ▼
UART 短动作 ID（规划链路）
      ▼
Arduino Nano 类控制板
      │ 舵机控制信号/动作组
      ▼
机械臂
```

显示与交互链路独立于机械臂控制链路：

```text
PYNQ HDMI OUT ───────────────→ 显示屏 HDMI
显示屏 TOUCH USB-C ─────────→ PYNQ USB-A Host
显示屏 5V2A USB-C ←───────── 独立 5V2A 电源
```

## 4. 物理接线说明

### 4.1 开发电脑与 PYNQ-Z2

| 电脑端 | PYNQ-Z2 端 | 通信类型 | 用途 |
|---|---|---|---|
| 网口 | RJ45 Ethernet | TCP/IP | Jupyter、Samba、网页调试和文件部署 |
| USB 口 | Micro-USB PROG/UART | 串口控制台 | 查看 Linux 启动日志和程序输出 |

当前项目常用板卡地址为 `192.168.2.99`。Micro-USB PROG/UART 仅作为板卡控制台使用，不承担机械臂 UART 控制。

### 4.2 有线耳机与 PYNQ-Z2

| 耳机端 | PYNQ-Z2 端 | 信号 |
|---|---|---|
| 3.5 mm TRRS 插头 | HP/MIC 接口 | 模拟麦克风音频 |

PYNQ-Z2 上的 ADAU1761 音频编解码器负责采集音频。当前程序按 48 kHz 采集，再转换为 16 kHz 单声道波形供 CAM++ 和 TC-ResNet3 使用。

有线耳机应连接 HP/MIC，不应误接到仅用于外部线路输入的 LINE IN。

### 4.3 PYNQ-Z2 与触摸显示屏

| PYNQ-Z2 端 | 显示屏端 | 方向 | 功能 |
|---|---|---|---|
| HDMI OUT | HDMI | PYNQ → 显示屏 | 传输 UI 图像 |
| USB-A Host | TOUCH USB-C | 显示屏 → PYNQ | 传输 USB HID 触摸数据 |
| 不连接 PYNQ 电源 | 5V2A USB-C | 独立电源 → 显示屏 | 为显示屏单独供电 |

当前 FPGA-10 使用 1280×720@60 Hz HDMI 时序传输画面，原生 UI 逻辑分辨率为 800×480，由软件缩放后送入 HDMI/VDMA。

显示屏的 TOUCH 口承担触摸数据通信；显示屏的 5V2A 口承担独立供电。两者应分开连接，避免显示屏负载直接压低 PYNQ USB Host 电压。

### 4.4 PYNQ-Z2 与 Arduino Nano 类控制板

规划采用 TTL UART 连接：

| PYNQ 侧 | Arduino 侧 | 说明 |
|---|---|---|
| UART TX | UART RX | PYNQ 向 Arduino 发送动作帧 |
| UART RX | UART TX | Arduino 返回 ACK、完成或故障状态 |
| GND | GND | 建立通信参考地 |

注意事项：

1. PYNQ I/O 为 3.3V 逻辑。
2. Arduino Nano 类控制板可能采用 5V TTL，必须根据实际型号核对。
3. 若 Arduino RX/TX 不是 3.3V 兼容接口，应加入合适的双向电平转换电路。
4. 当前 FPGA-10 Overlay 和 `app.py` 尚未正式启用机械臂 UART 发送，图中该链路属于待集成链路。
5. UART 引出接口、实际引脚、波特率和动作帧协议必须在接线前最终确认，不能直接占用当前 Micro-USB PROG/UART 控制台。

### 4.5 Arduino 与机械臂

Arduino 负责把 PYNQ 发来的短动作 ID 转换为机械臂动作组或多路舵机控制信号。建议至少实现：

- 上电初始姿态；
- 抓取、放置和复位动作；
- 多轴动作顺序和时间控制；
- 关节安全角度限制；
- 超时停止；
- 急停处理；
- 动作完成 ACK；
- 故障状态返回。

Arduino 与机械臂舵机的具体接线取决于实际控制板是多路 PWM、串行总线舵机还是厂家动作组控制接口。在缺少控制板原理图和协议说明时，不应直接假定其引脚、电压或通信协议。

## 5. 供电与共地

### 5.1 PYNQ-Z2

- 使用圆孔 DC 电源接口供电；
- 当前配置为 12V 适配器；
- J9 跳线保持 `REG`；
- 不使用显示屏或舵机电源反向给 PYNQ 供电。

### 5.2 触摸显示屏

- 使用独立 5V2A 电源；
- 电源连接显示屏的 `5V2A` USB-C 口；
- TOUCH USB-C 只连接 PYNQ USB-A Host，主要承担触摸数据。

### 5.3 Arduino 与机械臂舵机

- Arduino 和机械臂舵机应使用与其规格匹配的独立电源；
- 不能从 PYNQ I/O 引脚给舵机供电；
- 不建议由 PYNQ USB Host 直接承担多路舵机负载；
- 电源额定电压和电流应根据舵机数量、堵转电流和控制板规格确定；
- UART 通信时 PYNQ、Arduino 和电平转换电路必须具有共同参考地；
- 舵机动力地与控制地的连接方式应遵循实际机械臂控制板说明。

## 6. PYNQ 内部软件与硬件分工

### 6.1 PS / ARM Linux

PS 端运行 Ubuntu 22.04/PYNQ 环境，负责：

- `app.py` 主程序和系统状态机；
- 用户注册、声纹模板管理和 UI 状态；
- 音频预处理；
- CAM++ 非加速部分和声纹相似度判决；
- TC-ResNet3 命令识别；
- Linux USB HID 触摸事件读取；
- 命令映射、安全门控和后续 UART 调度。

### 6.2 PL / FPGA-10

PL 端主要负责：

- CAM++ HLS 算子加速；
- HDMI/VDMA 视频输出；
- ADAU1761 音频通路控制；
- AXI-Lite 寄存器控制；
- 通过 AXI HP 与 DDR 交换数据。

PS 与 PL 共用同一 FPGA-10 Overlay。程序启动时必须先初始化 HDMI/VDMA 并占用显示帧缓冲，再初始化音频、CAM++ 和 TC-ResNet3，避免完整程序启动后出现黑屏。

## 7. 触摸和界面通信

显示屏触摸控制器在 PYNQ Linux 中作为 USB HID 输入设备出现。当前实测设备为 `/dev/input/event0`，原始坐标范围为：

```text
ABS_X: 0～4096
ABS_Y: 0～4096
```

程序将 4096×4096 原始坐标映射到 800×480 逻辑 UI。当前已实现：

- 身份识别页面；
- 用户注册页面；
- 用户管理页面；
- 英文姓名和用户编号软键盘；
- 识别阈值触摸调整；
- 用户列表刷新和可恢复删除。

## 8. 推荐启动顺序

1. 确认 PYNQ、显示屏、Arduino/机械臂均使用各自正确的独立电源。
2. 断电状态下连接 HDMI、TOUCH USB、有线耳机、网线和调试串口。
3. 若尚未验证 UART 电平和引脚，不连接 PYNQ 与 Arduino 的 TX/RX。
4. 给显示屏独立上电并确认其输入源为 HDMI。
5. 给 PYNQ-Z2 上电，检查 DONE、LD 和串口启动日志。
6. 启动 FPGA-10 `app.py`，确认 HDMI UI、触摸、软键盘、音频和推理均正常。
7. 保持 `dry_run=true`，先完成无机械臂动作的整套识别测试。
8. 完成 UART 电平、引脚、波特率、协议、ACK、限位和急停验证后，再单独联调 Arduino。
9. 最后才允许把识别结果映射为真实机械臂动作。

## 10. UART 联调前必须确认的参数

在启用机械臂控制前，应形成明确的 UART 接口合同：

| 参数 | 待确认内容 |
|---|---|
| Arduino 型号 | Nano 原版或具体兼容板型号 |
| 逻辑电平 | Arduino RX/TX 是否兼容 3.3V |
| PYNQ 引脚 | 最终 UART TX、RX、GND 引出位置 |
| 波特率 | 例如 115200，必须由两端一致确认 |
| 数据格式 | 数据位、校验位、停止位 |
| 帧格式 | 帧头、序号、动作 ID、长度、CRC/校验 |
| 返回机制 | ACK、BUSY、DONE、FAULT、超时 |
| 安全策略 | 白名单动作、限位、重复帧处理、急停 |
| 电源规格 | Arduino 和舵机控制板的额定电压、电流 |

## 11. 结论

当前系统已经完成 PYNQ-Z2、音频、CAM++、TC-ResNet3、HDMI/VDMA、5 英寸触摸屏和英文软键盘的板端集成。显示屏通过 HDMI 和 USB HID 与 PYNQ 通信，并采用独立 5V2A 电源；PYNQ 使用独立 12V 圆孔电源。

机械臂控制方案确定为 `PYNQ UART → Arduino Nano 类控制板 → 机械臂舵机`。该链路目前仍处于设计和安全联调阶段，必须先确认实际 Arduino 型号、UART 电平、引脚、波特率、动作协议以及机械臂独立电源参数，再解除 `dry_run` 安全门控。
