# SonicArm 大模型协作过程报告

## 1. 报告目的

本报告对应《全国大学生嵌入式芯片与系统设计竞赛 2026 FPGA 赛道选题指南》中“大模型协作记录”的提交要求，记录 SonicArm 在方案设计、HLS/RTL 加速、PYNQ 软件、模型部署、系统集成、验证与技能包提炼过程中使用大模型和智能体的实际方式。

报告包含：

1. 代表性用户提示词；
2. 大模型回答与执行摘要；
3. 失败、质疑、修正和重新验证形成的自我纠错轨迹；
4. 对应源码、报告、日志和测试产物；
5. 人工决策、大模型能力与硬件实测之间的边界。

本报告不是用大模型回答替代工程证据。模型建议只有在经过源码检查、仿真、综合、实现报告或板端实测后，才被写入相应证据层级。

## 2. 使用方式与责任边界

- 协作工具：Codex 编程智能体；部分方案评审中还使用了其他公开大模型给出的建议，再由 Codex 和项目成员审查。
- 人工职责：确定项目目标、提供硬件与数据、授权文件修改、执行板端操作、确认机械臂动作安全并决定最终采用方案。
- 智能体职责：检索和检查源码、生成或修改代码、编写测试、调用 Vivado/Vitis HLS 脚本、解析报告、整理文档和构建可复用 Skill。
- 禁止越界：没有实际执行的板端、Vivado 或物理动作不写成已验证；HLS 估计不写成布局布线结果；单算子通过不写成整网加速。

## 3. 记录来源与覆盖范围

本报告综合检查了以下来源：

- Codex 中工作目录为 `SonicArm` 的项目聊天标题、摘要及可读取回合；
- `report/development_history.md` 和 `report/validation/`；
- `data/archive/` 中各 FPGA 版本的交接、失败记录与验证说明；
- `skill/docs/`、`skill/evals/` 和五个 PYNQ Skill；
- HLS、Vivado、离线测试及板端结果文件。

历史聊天接口按页返回内容，部分长聊天会被截断；已删除聊天、外部平台聊天和未保存的临时对话无法逐字恢复。因此，本报告采用“可审计的代表性交互 + 全部可定位聊天索引”的方式，不伪造缺失回答，不把摘要声称为逐字原文。

为保护隐私，个人账号、临时附件路径、设备网络地址和无关私人内容未写入公开报告。

## 4. 代表性协作记录

### 4.1 从项目设想到 PYNQ 实现路线

**关联聊天**：`PYNQ声纹加速-1`，线程 `01a11e68-8a72-74a2-b7cf-18888221bafe`。

**用户提示词摘录**：

> 我计划拿这个参加 FPGA 嵌入式竞赛，请先协助开发 PYNQ 端声纹验证器。如何部署加速识别方案？以前的 CCS 声纹识别代码是否有参考价值？

**模型回答与执行摘要**：

- 建议采用 PS/PL 协同路线：Jupyter/Python 负责数据准备、Overlay 调用和调试，Vivado/Vitis HLS 负责可综合硬件核；
- 将旧 CCS 工程用于理解预处理、权重布局和推理流程，但不直接假设 DSP 实现可移植到 Zynq-7020。

**自我纠错轨迹**：

1. 初期设想倾向于“计算密集任务全部放入 PL”；
2. 检查 CAM++ 网络、PYNQ 资源与软件依赖后，修正为“热点算子进入 PL，控制与不适合硬件化的算子留在 PS”；
3. 在板卡启动故障排查中，模型没有把“串口无输出”直接判定为供电故障，而是先检查镜像校验、SD 启动跳线和启动分区；
4. 项目成员完成镜像校验后，才继续判断供电和板卡状态。

**对应产物**：`data/archive/fpga2_conv_relu/`、`data/archive/fpga4_fcm/`、`report/development_history.md`。

### 4.2 单算子加速到可复现 HLS 验证

**关联聊天**：`PYNQ声纹加速-2`，线程 `01a1399d-8d9f-79e2-b7ab-7d33cd36a2ef`。

**用户提示词摘录**：

> 已完成第一版单层 FPGA 加速，下一步如何扩大加速范围，并保证输出和软件模型一致？

**模型回答与执行摘要**：

- 从 ONNX 图中提取卷积、量化、ReLU 等连续计算段；
- 建立 C/C++ 黄金模型、自检 testbench、故意错误的负控测试以及 NumPy bit-accurate 对照；
- 分开执行 C simulation、C synthesis、RTL co-simulation，并保存每阶段日志。

**自我纠错轨迹**：

1. HLS C simulation 首次失败，日志表明 Vitis HLS 2025.2 的配置节位置错误；
2. 将 `flow_target` 调整到正确的 `[hls]` 配置节后，同一测试通过；
3. RTL co-simulation 随后因接口深度不足失败；
4. 根据真实最大输入调整 testbench 深度，再次执行，最终 2/2 事务通过；
5. 综合虽然成功，但报告暴露动态循环上界、顺序除法器、8 位 `m_axi` 和 missed burst 问题，因此保留为功能原型，不宣称已经达到可用带宽。

**回答摘录**：

> HLS C simulation 已通过。第一次失败仅是 2025.2 配置节格式问题，修正后同一测试通过。现在进入 C synthesis，结果仍只属于 HLS 估计。

> 综合完成，但动态 Pool 循环、整数除法和窄 `m_axi` 是必须先修的架构问题；当前只是功能原型。

**对应产物**：各版本 HLS 源码、testbench、`csynth.rpt`、`cosim.rpt` 以及 `data/archive/` 内的阶段报告。

### 4.3 双核方案到统一计算核

**关联聊天**：`构建 CAM++ 全模型测试`、`FPGA-6加速器`，线程 `01a13bd1-103d-7990-9570-2df3e4e6b894`、`01a148b9-bad5-7220-8b79-f152d313ab8d`。

**用户提示词摘录**：

> 在 PYNQ-Z2 上继续扩大 CAM++ 的 FPGA 覆盖，分析资源、时序和整网性能。

**模型回答与执行摘要**：

- 分别分析 Pointwise 与 FCM 两类热点，再比较双核与共享核的资源代价；
根据 PYNQ-Z2 的 DSP/BRAM 上限，将两个路径重构为按模式复用 MAC 阵列的统一核。

**自我纠错轨迹**：

1. 双核实现可以覆盖更多算子，但资源接近器件上限；
2. 仅增加并行通路没有得到等比例整网收益，DDR 往返与 PS/PL 调用成为瓶颈；
3. 项目放弃“继续堆叠独立核”的路线，改成统一核和共享数据通路；
4. 资源减少和时序通过只按实现报告记录，不把资源优化自动解释为整网精度或端到端性能通过。

**对应产物**：`data/archive/fpga5_dual_kernel/`、`data/archive/fpga6_validated_kernels/`、`data/archive/fpga7_unified_kernel/`、`report/fpga/`。

### 4.4 短语识别模型的部署选择

**关联聊天**：`评估短语识别模型部署方案`，线程 `01a1641d-4d82-7e53-8f19-51beb88faec6`。

**用户提示词摘录**：

> 结合现有 CAM++ 声纹识别资源占用和 TC-ResNet 模型大小，评估短语识别是否继续放入 FPGA，以及怎样与声纹鉴权集成。

**模型回答与执行摘要**：

- 比较 PL 剩余资源、模型规模、数据搬运和控制复杂度；
- 建议短语模型先部署在 PS，声纹通过后再触发分类，形成双门限安全链；
- 建立桌面 NumPy/ONNX 一致性检查和板端包，保留后续硬件化接口。

**自我纠错轨迹**：

1. 初始模型包使用 TC-ResNet2，执行开关保持关闭；
2. 真实录音回归和部署需求变化后升级到 TC-ResNet3；
3. 合成音频表现不能替代真人与板端录音，因此最终 README 分别报告两类数据；
4. 分类置信度与机械臂执行解耦，只有身份、指令阈值和状态机同时通过才发动作。

**对应产物**：`src/models/kws/tc_resnet3/`、`src/ps/controller.py`、`src/ps/v9_core.py`。

### 4.5 音频、Overlay、显示和触摸集成

**关联聊天**：`规划显示屏声纹识别部署`、`规划SonicArm上板集成部署`、`新增用户管理 UI 页面`，线程 `01a162b7-4122-7913-b360-52052f6db38b`、`01a16849-262f-7b70-8960-421f23f1b66d`、`01a16901-12f6-7a92-bbb5-c04eab743d78`。

**用户提示词摘录**：

> 将耳机音频、声纹识别、触控屏、用户注册和机械臂控制整合到同一套 PYNQ 应用中，确认 Overlay、HDMI 和 USB 触摸的实现方式。

**模型回答与执行摘要**：

- 梳理 ADAU1761 音频、CAM++ 核、VDMA/HDMI、USB HID 和 PS 应用的数据流；
- 避免重复加载导致音频和显示互相破坏；
- 协助调试原生 HDMI 帧泵、触摸坐标映射、Web 调试镜像及注册/用户管理页面。

**自我纠错轨迹**：

1. 最初把浏览器 UI 和 HDMI 输出理解得过于接近；
2. 检查 PYNQ-Z2 显示链路后确认 HDMI OUT 是 PL VDMA 视频流，不是 Linux 桌面；
3. 因此增加 PS 原生渲染与 frame pump，而不是假设浏览器会自动出现在显示屏；
4. 一次 VDMA 中断直连实验导致蓝屏回归，随后撤销该连接，保留同步 MM2S 软件通道并记录失败版本。

**对应产物**：`src/ps/native_display.py`、`src/ps/ui/`、`report/validation/DISPLAY_REQUIREMENTS.md`、`report/validation/FPGA10_STATUS_20261027.md`。

### 4.6 机械臂控制与安全状态机

**关联聊天**：`规划SonicArm上板集成部署`、`撰写语音识别技术文档`，线程 `01a16849-262f-7b70-8960-421f23f1b66d`、`01a192d5-c2ac-7273-82de-4e5f48e7d32f`。

**用户提示词摘录**：

> 将声纹鉴权、短语识别和机械臂串口动作整合，增加上电复位、语音复位和动作状态反馈，并形成可提交的测试记录。

**模型回答与执行摘要**：

- 将模型输出与物理执行分开，通过身份门限、指令门限、动作白名单和状态机门控；
- 扫描串口设备并通过握手识别控制板，不依赖固定端口号；
- 对动作等待、重复请求、故障状态和复位路径进行离线测试。

**自我纠错轨迹**：

1. 旧 Notebook 中右放动作等待时间不足；
2. 根据实际动作周期延长等待时间，避免动作未完成就进入下一状态；
3. 串口异常时进入 FAULT，不自动重发，降低重复动作风险；
4. 软件测试通过和机械臂物理安全分开记录，未用接口调用成功替代真实动作验收。

**对应产物**：`src/ps/arm_integration.py`、`src/ps/arm/verified_arm_control.py`、`sim/tests/test_arm_integration.py`、`report/validation/ARM_INTEGRATION.md`。

**用户提示词摘录**：

> 整理部署版本、20 次现场任务、声纹与短语结果、端到端时延以及 FPGA 资源/时序，生成技术文档大纲。

4. 技术文档中的关键结论要求回链到 JSON、CSV、Vivado 报告或板端日志。

### 4.8 PYNQ Skill 的提炼与独立验证

**关联聊天**：`构建并测试 PYNQ Agent Skill 套件`、`验证 PYNQ-Z2 AXI GPIO 迁移`，线程 `01a19381-2d66-7753-9aad-722587760171`、`01a1939d-911f-71f3-ab11-cadbc281400a`。

**用户提示词摘录**：

> 把 SonicArm 开发过程中形成的 Overlay、IP 驱动、数据通路和证据验证经验提炼为可复用 Skill，并用另一个 PYNQ 例程验证迁移能力。

**模型回答与执行摘要**：

- 将经验拆分为 `pynq-overlay-audit`、`pynq-ip-driver`、`pynq-data-path`、`pynq-validation` 和总路由 `pynq-workflow`；
- 为每个 Skill 提供合同模板、脚本、测试和失败条件；
- 使用 SonicArm HWH 静态审计和独立 AXI GPIO 例程进行迁移验证。

**自我纠错轨迹**：

1. 首次 HWH 审计把同一 PS7 实例的重复地址声明误判为重叠；
2. 修正解析器，使其不比较同一实例重复范围，并增加回归测试；
3. 缺少可信共构建 manifest 时，bit/HWH 身份保持 `INCONCLUSIVE`，没有改写为 PASS；
4. 硬件未执行的检查统一标为 `NOT_RUN` 或 `HARDWARE_NOT_RUN`。

**回答与证据**：`skill/docs/ai_collaboration_evidence.md`、`skill/docs/skill_development_report.md`、`skill/evals/results/`。

## 6. 典型纠错模式总结

| 初始判断或失败 | 纠错依据 | 修正结果 |
| --- | --- | --- |
| 串口无输出可能是供电 | 镜像校验、启动分区、跳线和串口逐项检查 | 先修复并验证镜像，再判断供电 |
| HLS C simulation 失败 | 2025.2 日志指出配置节错误 | 修正配置后重跑通过 |
| RTL co-simulation 失败 | 日志指出接口深度不足 | 按最大输入调整 testbench 后通过 |
| 综合成功即可继续上板 | 报告显示窄总线、missed burst、动态循环与除法器 | 仅标记功能原型，保留优化任务 |
| 浏览器界面可直接显示在 HDMI OUT | PYNQ-Z2 VDMA 链路和实物测试 | 改成 PS 原生渲染与帧泵 |
| VDMA 中断直连有利于刷新 | 实物显示回归为蓝屏 | 撤销直连并恢复同步 MM2S |
| 两个独立加速核覆盖更多算子 | PYNQ-Z2 资源与端到端收益对比 | 改为统一核复用 MAC 阵列 |
| HWH 地址重复就是冲突 | 同一 PS7 实例重复声明分析 | 修正审计器并增加回归测试 |
| 有 bit/HWH 即可认定配对 | 缺少可信共构建 manifest | 身份状态保持 `INCONCLUSIVE` |
| 根目录许可证可覆盖全部文件 | 第三方版权与数据授权审计 | Apache-2.0 仅覆盖团队自研内容 |

## 7. 复核方法

评审者可以按以下顺序复核本报告：

1. 阅读 `report/development_history.md` 确认版本演进；
2. 查看 `report/fpga/` 中综合、实现、时序与资源报告；
3. 运行 `sim/run_tests.ps1` 检查 PS 软件离线测试；
4. 运行 `skill/tests/test_suite.py` 和 `skill/evals/run_evaluation.py` 检查 Skill；
5. 对照上述线程标识查看原始 Codex 聊天；
6. 使用 `SOURCE_MANIFEST.json` 核对提交文件身份。

## 8. 结论

大模型在 SonicArm 中承担了方案拆解、错误定位、自动化验证、报告解析和经验提炼工作，但最终结论由可复现工程证据约束。项目保留了多次失败、回退和边界收缩：配置错误修正、co-simulation 深度修正、VDMA 中断回退、统一核重构、HWH 审计器修正以及第三方许可拆分。这些记录体现了大模型协作不是一次性生成答案，而是“提示—执行—失败—诊断—修正—复验”的闭环过程。
